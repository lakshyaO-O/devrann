# DevRann feature inventory and enhancement roadmap

This is a source-based inventory, not a claim that every route has been manually exercised in production. The working tree already contains substantial, uncommitted changes from the preceding security remediation; do not deploy those changes as a unit until they are reviewed and the Firestore emulator suite passes.

## Free/open-source operating constraint

Use open-source software and existing free-tier services only; do not add paid API/model subscriptions or paid product plans as implementation dependencies. Firebase/Vercel free tiers still have quotas and can require billing for production scale, so check the current project plan and usage before enabling traffic-heavy features. Judge0 Community Edition can be self-hosted without a license fee, but needs a Linux host with adequate CPU/RAM and operational maintenance; the public CE endpoint is for evaluation, not a production dependency. AI assistance should remain explicitly unavailable when no free provider is configured; a local Ollama-compatible provider may be offered as an optional self-hosted path, subject to the operator’s hardware. Do not silently substitute paid APIs or claim these services are provisioned.

## Data/security notes

- Primary data is in Firestore: `users` and user subcollections (`submissions`, `progress`, `practiceProgress`, `matches`, `gameHistory`, `friends`, `friendRequests`, `notifications`, `challenges`, `achievements` and other feature data); top-level `publicProfiles`, `problems`, `problemContent`, `problemSecrets`, `battles`, `matches`, `matchmaking`, `gameRooms`, `invites`, `leaderboard`, `communityPosts`, `forum*`, `studyGroups`, `contests` and administration/configuration collections.
- The `users` document contains private account fields and protected metrics; public profile fields must be projected, not served by unrestricted reads.
- The local Firestore Emulator test setup is configured in `firebase.json`, and the test suite uses `demo-devrann-rules`. `npm run test:rules` is currently blocked because no Java runtime is installed. No rules or indexes have been deployed.
- `.firebaserc` names `codexarena-4990f`; this project was confirmed by the user as the intended production Firebase project. Confirmation is not proof of deployed state.
- The checkout is linked to the Vercel project `devrann`, but the Vercel CLI is unavailable. Git remote points to the repository’s `main` branch; pushing the current dirty tree would include unrelated accumulated changes and is unsafe.

## Release gates

1. Review the complete pre-existing working-tree diff and separate intended changes from unrelated edits.
2. Install a supported JDK and run `npm run test:rules`; add route/API tests for trusted-server operations.
3. Run unit tests, typecheck, lint and production build after the final changes.
4. Confirm judge provider, production environment variables, judge health and Firestore indexes.
5. Back up the currently deployed rules, review the final rules diff and deploy rules only after Emulator verification.
6. Deploy the reviewed application through the verified Vercel project/preview first; production promotion requires successful smoke checks for auth, public routes, practice, profile privacy, friends and protected writes.
